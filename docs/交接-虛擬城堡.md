## 2. 管理員的偏好與已定事項

- 使用繁體中文（台灣用語），說明要淺顯，少用難懂的術語。
- 城堡是 `CLAUDE.md` 的第三個例外：可以依需要導入框架或函式庫。
- NPC 用真實成員暱稱；外觀與台詞不夠時，可以自行生成示範資料（標 `is_demo: true`，畫面會顯示「示範資料」）。不用在意角色性別。
- 個人台詞由管理員收集。
- 手機操作：先用「點地板走過去」，之後再視需要加虛擬方向盤。
- **做好一個可以玩的版本，就開 PR 並直接合併到 `main`**（管理員想直接在網站上看；合併後 GitHub Pages 約 1～3 分鐘更新）。合併前先跑完第 5 節的驗證；改動很大或不確定時，先開 PR 問管理員。
- 精美圖片由管理員用網頁版 ChatGPT 產生（可輸出透明背景 PNG）。AI 代理負責寫規格與提示詞（`docs/素材規格-城堡圖片.md`），收到圖片後負責裁切、縮放、放進遊戲。
- 不可使用遊戲官方的美術素材或 LOGO，也不要模仿特定遊戲的畫面。

## 3. 程式地圖（只列城堡相關）

| 檔案 | 用途 |
|---|---|
| `hall.html` | 城堡頁，先載入 `assets/vendor/phaser/phaser.min.js`（Phaser 3.90.0），再載入 `assets/js/pages/hall.js` |
| `assets/js/pages/hall.js` | 讀資料（`members`、`castle_looks`、`castle_lines`）→ 啟動遊戲；處理網址參數 |
| `assets/js/castle/config.js` | 所有可調數值：格子 32px、畫面 640×360（放大 2 倍繪製）、速度、NPC 上限、行為機率、地圖配色 |
| `assets/js/castle/main.js` | 抽選成員、建立 Phaser 遊戲、對話框與提示訊息 |
| `assets/js/castle/RoomScene.js` | **唯一的房間場景**：載入圖片、碰撞、放訪客與 NPC、互動、換房間 |
| `assets/js/castle/roomView.js` | 畫房間（只管外觀）：色塊備案 → 地板與牆的拼貼圖 → 家具與門的圖片 → 文字標籤 |
| `assets/js/castle/art.js` | **圖片清單**：名稱 → 檔案、大小（格數）。只登記已有成品的圖；`WANTED_ART` 是房間已指定、還沒有圖的名稱 |
| `assets/js/castle/music.js` | 公會歌播放器（HTML 按鈕＋`Audio`，不經 Phaser；遊戲載入失敗也能聽） |
| `tools/castle_images.py` | 圖片處理（手動執行）：讀 `art.js` 的大小，把 `docs/素材/城堡原圖/` 裁切縮放成 `assets/images/castle/*.webp` |
| `assets/js/castle/rooms/*.js` | 房間定義：文字地圖、`legend`（字元→種類與顏色）、門、出生點、演出點、可查看的物件、文字標籤 |
| `assets/js/castle/grid.js` | 解析文字地圖、能不能走、格子尋路、格子預約（避讓） |
| `assets/js/castle/npc.js` | NPC 狀態機：idle／walk／perform／talk |
| `assets/js/castle/actions.js` | 演出動作表（姿勢、是否坐著、泡泡文字、停留秒數） |
| `assets/js/castle/avatar.js` | 幾何色塊外觀。行為只呼叫 `setPosition`／`setFacing`／`setPose`／`say`，日後換像素角色時另寫一個同介面的類別 |
| `assets/js/castle/player.js` | 訪客操作 |
| `assets/js/castle/roster.js` | 抽選、分配房間、自動配色、挑台詞 |
| `assets/js/castle/dialog.js` | 對話框（HTML、`textContent`） |
| `assets/js/castle/debug.js` | `?debug=1` 除錯圖層、`window.__castle` 狀態、房間定義檢查 |
| `data/castle_looks.json`、`data/castle_lines.json` | 外觀與台詞（平面資料表，目前都是示範資料） |

圖片規則：房間的 `legend` 用 `sprite: '名稱'` 指定圖片（`flipX: true` 左右翻轉、`under: 'stage'` 指定家具底下鋪什麼）；門的定義也可以寫 `sprite`、`under`。名稱在 `art.js` 有登記且載入成功就用圖，否則畫 `color` 色塊。同一個字元連成一片時，依 `art.js` 的寬 `w` 與佔地列數 `foot` 一件一件放（例如一排椅子）。

地圖字元規則：`#` 牆、`.` 地板、`r` 地毯、`s` 舞台；家具在各房間的 `legend` 定義，`kind` 為 `furniture`（不能走）、`seat`（只有要坐的 NPC 能進去）、`wall`；門的字元寫在 `doors`，有 `to` 是可通行的門，有 `locked` 是整修中的門。

## 5. 驗證方式（不建立測試框架，在工作階段中手動跑）

0. **先跑自動檢查**：`node tools/check_castle.mjs`（不用安裝套件）。房間定義、門與出生點、圖片登記／成品／原圖／`WANTED_ART`、資料表、相對路徑與 innerHTML 都會檢查；通過才往下。
1. 啟動本機伺服器：`python -m http.server 8020 --bind 127.0.0.1`（管理員電腦上 8000 已被其他專案登記；開埠前先查並登記 `D:\UserData\Documents\WS\共用指南\登記表-本機連接埠（ports）.md`。雲端環境用哪個埠都可以）。
2. 用 Playwright（雲端環境已內建，`require('playwright')`；管理員電腦沒有，改用 Chrome 擴充）開 `http://127.0.0.1:8020/hall.html?seed=1&debug=1`：
   - 主控台沒有錯誤。
   - 讀 `window.__castle`：`problems` 為空陣列（房間定義沒問題）、每個 NPC 的 `tileOk` 為 true、沒有兩個 NPC 在同一格。
   - 用 `window.__castleGame.scene.getScene('room')` 操作：`player.walkTo(x, y)` 讓訪客走到某格、`player.feet.body.reset(x, y)` 直接移動訪客、`scene.restart({ roomId: 'music', spawn: 'from_hall' })` 換房間。
3. Python 檢查 `data/castle_*.json`：能解析、沒有巢狀值、`member_id` 對得到成員、顏色是 `#rrggbb`。
4. `grep` 確認沒有以 `/` 開頭的路徑、沒有把資料放進 `innerHTML`。
5. 圖片：`window.__castle.art` 的 `used` 是用到的圖、`missing` 是還沒有圖（畫色塊）的名稱；網址加 `&noart=1` 確認全部改畫色塊時也能正常玩。
6. 截圖只在最後檢查一兩張；平常用 `window.__castle` 判斷，節省時間。

## 6. 踩過的坑

- **雲端環境的網路**：cdnjs、unpkg、jsdelivr 被擋，`registry.npmjs.org` 可以連（Phaser 就是從那裡下載 `phaser-3.90.0.tgz` 並核對檢查碼）。`bubblesdream.github.io` 也連不到，無法在雲端確認正式網站，請管理員自己看。
- **無頭瀏覽器很慢**（約每秒 13 格畫面）。Phaser 預設會把每格時間抹平成 1/60 秒，導致角色變慢，所以設定了 `fps: { smoothStep: false }`。不要拿掉。
- 點地板自動走路時，最後一格要減速，不然掉格時會在目標附近來回晃（`player.js` 已處理）。
- 鍵盤只在遊戲區取得焦點時作用（Phaser `input.keyboard.target` 設成遊戲區元素），所以沒點遊戲時方向鍵仍可捲動網頁。
- 測試時點擊畫面會觸發「點地板走路」，之後再呼叫 `walkTo` 要先等 0.5 秒，不然會被點擊的路線覆蓋。
- 成員頭像圖片還沒同步，其他頁面會出現 404 再換成佔位圖，這是正常現象。
- **地板接縫**：拼貼圖若一格一格用 `add.image` 擺，畫面捲動時格子之間會出現細線，所以地板、牆畫進一張兩倍大的 `RenderTexture`（圖片原尺寸、整數位置），再縮成一半顯示。
- 還沒有圖的家具色塊要畫在拼貼圖**上面**（depth -8），不然會被地板圖蓋住看不見。
- 原圖約 1～2 MB 一張，只放在 `docs/`，網站只讀 `assets/images/castle/` 的小圖（全部約 530 KB）。
- **瀏覽器分頁在背景會被降到每秒 1 格畫面**，角色看起來亂跑、走不到目的地。測試移動時改用手動推進：`let t = performance.now(); for (let i = 0; i < 60 * 秒數; i++) { t += 1000 / 60; window.__castleGame.step(t, 1000 / 60); }`，結果穩定。
- 同一個字元連成「不是長方形」的一片（例如圍成一圈的柵欄），只在真的有該字元的格子放圖（`roomView.js` 的 `findSprites`）；以前會把整個外框範圍填滿。
- 管理員把圖拿回本機時，曾出現「同一張圖、像素相同但檔案大小不同」（重新壓縮過）。比對要比像素，不要只比檔案。
