
# 專案：第一交響樂團｜公會紀念網站

你是一名具有 UI/UX 設計能力的資深前端工程師。

請幫我建立一個部署於 GitHub Pages 的公會紀念網站。

## 一、專案定位

網站名稱：**第一交響樂團**

這是一個遊戲公會的數位紀念館，用來保存公會歷史、成員、遊戲截圖、YouTube 影片及共同回憶。

網站主要用途：

- 記錄公會走過的歷史
- 展示公會成員與遊戲角色造型
- 收藏歷年影片與照片
- 作為公會對外展示的網站
- 未來增加可走動的 2D 虛擬公會大廳

網站更新頻率可能很低，因此不需要以公告或即時消息為中心。

## 二、視覺設計

採用「日系遊戲回憶錄 × 簡潔部落格 × 數位相簿」風格。

設計要求：

- 簡潔、自然、有溫度
- 像玩家自己用心整理的公會紀念網站
- 以照片、遊戲截圖、故事為主要視覺
- 留白適當，文字容易閱讀
- 使用簡單卡片、相簿和文章版面
- 支援桌面與手機瀏覽
- 保留後續調整版型的彈性

避免：

- 金色發光邊框
- 過量漸層、粒子與光效
- 華麗奇幻遊戲商城風格
- 大量無意義動畫
- 常見 AI 生成網站的浮誇視覺
- 過度設計的控制面板

整體請參考簡潔的個人部落格、攝影作品集及遊戲社群紀念網站。

圖片先使用清楚標記的佔位素材，未來由我提供正式截圖和人物圖片。

## 三、網站架構

### 1. 首頁

包含：

- 網站 LOGO 與導覽列
- 公會合照大橫幅
- 公會名稱與一句簡短介紹
- 我們的故事（摘要）
- 精選回憶照片
- 公會成員預覽
- 精選 YouTube 影片
- 網站頁尾

請讓首頁簡潔，不要把所有資料一次塞進去。

### 2. 公會故事

用來記錄：

- 公會創立原因
- 公會名稱由來
- 重要歷史事件
- 歷任會長
- 不同遊戲時期的經歷

採用時間軸與文章混合的呈現方式。

每個歷史事件可以包含：

- 日期或年份
- 標題
- 文字內容
- 圖片
- 相關影片（選填）

### 3. 公會成員

使用人物卡片展示成員。

每位成員包含：

- 遊戲暱稱
- 個人頭像
- 簡短介紹
- 公會職位（選填）
- 個人詳情頁
- 造型收藏

角色詳情頁要能切換不同造型圖片，類似簡易遊戲角色圖鑑。

先採用切換完整圖片的方式，不需要實作分層紙娃娃系統。

未來可以增加更多造型、表情、服裝與背景。

### 4. 影片回顧

建立 YouTube 影片展示頁。

功能：

- 顯示影片縮圖
- 影片標題
- 發布日期
- 簡短介紹
- 點擊觀看 YouTube 影片
- 可依年份或遊戲分類

影片資料要容易新增和修改。

### 5. 公會紀念館

類似數位相簿。

內容包含：

- 公會合照
- 遊戲截圖
- 特殊活動
- 難忘的事件
- 公會經典語錄

可依年份或分類瀏覽。

點擊圖片可放大觀看，並顯示簡短文字說明。

### 6. 虛擬公會大廳（預留）

未來希望製作一個簡單的 2D 小遊戲。

構想：

- 玩家可以操控小角色走動
- 可與場景中的物品互動
- 可以觀看公告板、相簿
- 可以與公會成員角色互動
- 支援鍵盤及手機觸控操作

**第一版只建立預留入口或介紹頁，不實作遊戲本身。**

未來可能使用 Godot Web Export 或 HTML5 Canvas 製作。

## 四、技術要求

部署平台：GitHub Pages。

優先使用：

- HTML
- CSS
- JavaScript
- JSON

可以使用少量輕量套件，但請優先保持架構簡單。

要求：

- 靜態網站
- 不需要伺服器
- 不需要登入系統
- 不需要傳統資料庫
- 支援 RWD 響應式排版
- 手機可以正常操作
- 避免不必要的大型框架
- 頁面載入速度合理
- 網站可直接部署於 GitHub Pages
- 正確處理 GitHub Pages 專案子路徑與重新整理問題

## 五、資料管理

希望未來可以使用 Google 試算表管理網站內容。

預計管理項目：

- 公會成員
- YouTube 影片
- 公會歷史
- 照片資訊
- 紀念館內容

第一版先使用本地 JSON 儲存示範資料。

請將資料與畫面分離，讓未來能改成從公開 Google 試算表 CSV 讀取。

請預留清楚的資料載入模組。

注意安全：

- 外部文字資料以純文字方式顯示，避免 XSS
- 驗證圖片與影片網址
- 不將 API Key、密碼等機密資料放在前端
- YouTube 僅允許合理的影片網址格式
- Google 試算表未來只存放可公開資訊

不需要建立真正的管理後台。

## 六、第一版完成範圍

請實作：

1. 網站首頁
2. 公會故事頁
3. 成員列表與個人詳情頁
4. 成員造型圖片切換
5. YouTube 影片列表
6. 公會紀念館與圖片放大
7. 虛擬大廳預留入口
8. 手機版響應式設計
9. 本地 JSON 資料管理
10. GitHub Pages 部署設定

示範內容請清楚標示為假資料，避免將虛構的公會歷史、人物、日期當成真實資料。

## 七、開發原則

這個專案將持續擴充，因此請注意：

- 保持專案結構容易理解
- 元件與樣式避免重複
- 所有網站內容應容易替換
- 不要過度工程
- 不要自行追加大量功能
- 優先建立完整可運作的 MVP
- 不需要建立測試框架或複雜 CI 流程
- 基本功能與部署仍須經過適當驗證

## 八、執行方式

請先檢查目前 GitHub 儲存庫的內容。

如果已有專案，請沿用合理的既有架構，避免覆蓋重要檔案。

接著：

1. 簡短說明你選擇的技術方案與目錄結構。
2. 直接建立第一版網站。
3. 建立必要的 JSON 示範資料。
4. 建立 README，說明如何修改成員、照片、影片與歷史資料。
5. 設定 GitHub Pages 部署方式。
6. 執行可行的基本驗證。
7. 最後整理完成項目、未完成項目及部署步驟。

若目前環境允許，請透過獨立分支與 Pull Request 提交，方便我審查後合併。

請避免進行與本次網站無關的修改。

**最重要的要求：網站先求簡單、實用、自然、有回憶感。不要做成過度華麗的 AI 展示網站。**
