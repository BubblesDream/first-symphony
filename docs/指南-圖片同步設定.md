# 圖片同步設定指南

這份指南寫給第一次接觸 Google Cloud 的管理員。照著做一次就好，之後每天會自動同步。

整個流程是這樣：

```
Google 雲端硬碟「管理員專用」資料夾
   ↓（每天一次，GitHub 自動執行）
轉成網站用的 WebP 小圖
   ↓
自動開一個 Pull Request（變更申請）
   ↓（管理員檢查後按「合併」）
網站幾分鐘內更新
```

需要準備：一個 Google 帳號（能看到「管理員專用」資料夾的那個）、GitHub 專案的管理權限。

---

## 一、建立 Google Cloud 專案

「service account（服務帳戶）」是給程式用的 Google 帳號。GitHub 會用它去讀雲端硬碟，所以要先建一個。

1. 打開 <https://console.cloud.google.com/>，用你的 Google 帳號登入。第一次進入要同意服務條款。
2. 畫面最上方、Google Cloud 字樣旁邊有一個「選取專案」的下拉選單，點它 →「新增專案」。
3. 專案名稱填 `first-symphony-sync`（隨意，自己認得就好）→「建立」。
4. 建好後，確認上方下拉選單已經切換到這個新專案。

> 這個流程只用到免費的功能，不需要綁信用卡。如果畫面要求你開啟計費，多半是點錯地方了，可以先返回。

## 二、啟用 Google Drive API

1. 左上角「☰」選單 →「API 和服務」→「程式庫」。
2. 搜尋框輸入 `Google Drive API`，點進搜尋結果。
3. 按「啟用」。

## 三、建立 service account 並下載金鑰

1. 左上角「☰」→「IAM 與管理」→「服務帳戶」。
2. 上方「＋ 建立服務帳戶」。
3. 服務帳戶名稱填 `image-sync`，下方的 ID 會自動帶出 →「建立並繼續」。
4. 「授予這個服務帳戶專案存取權」與「授予使用者存取權」兩個步驟都**不用填**，直接按「完成」。
5. 回到清單，會看到一個像 `image-sync@first-symphony-sync.iam.gserviceaccount.com` 的 email，**先複製起來**，第四步會用到。
6. 點這個服務帳戶 → 上方分頁「金鑰」→「新增金鑰」→「建立新的金鑰」→ 選「JSON」→「建立」。
7. 瀏覽器會下載一個 `.json` 檔，這就是金鑰。

> **金鑰等於密碼。** 不要傳到群組、不要放進雲端硬碟分享資料夾、不要放進這個 GitHub 專案的檔案裡。它只需要貼到 GitHub 的 Secrets（第五步）。貼完後可以把檔案存到只有你自己看得到的地方，或直接刪掉（需要時再建一把新的）。
>
> 如果 Google 顯示「機構政策禁止建立服務帳戶金鑰」，代表你用的是公司或學校帳號，請改用個人 Gmail 帳號建立專案。

## 四、把資料夾分享給 service account

1. 打開 Google 雲端硬碟，找到「第一交響樂團｜網站（管理員專用，不要分享）」資料夾。
2. 在資料夾上按右鍵 →「共用」→「共用」。
3. 「新增使用者」欄位貼上第三步複製的 service account email。
4. 權限選「**檢視者**」（只能看，不能改）。
5. 取消勾選「通知使用者」（service account 收不到信），按「共用」。

> 只分享「管理員專用」這一個資料夾，不要分享「投稿區」或整個雲端硬碟。

順便記下資料夾 id：打開這個資料夾，網址列會像
`https://drive.google.com/drive/folders/15kYNAy8PwyNyIubTE-dhtPXJlg9o3Z-A`，
最後一段 `15kYNAy8PwyNyIubTE-dhtPXJlg9o3Z-A` 就是資料夾 id。

## 五、GitHub 設定

到 GitHub 專案頁 <https://github.com/BubblesDream/first-symphony>，點上方「Settings」（齒輪圖示）。

### 1. 新增 Secret：金鑰

1. 左側「Secrets and variables」→「Actions」。
2. 「Secrets」分頁 → 綠色按鈕「New repository secret」。
3. Name 填 `GDRIVE_SA_KEY`。
4. Secret 欄位：用記事本打開第三步下載的 `.json` 檔，**全選、複製整個內容**貼上（從第一個 `{` 到最後一個 `}`）。
5. 按「Add secret」。

存進去之後 GitHub 不會再顯示內容，執行紀錄裡也會自動遮蔽，這是正常的。

### 2. 新增 Variable：資料夾 id

1. 同一頁切到「Variables」分頁 →「New repository variable」。
2. Name 填 `GDRIVE_ROOT_FOLDER_ID`。
3. Value 填第四步記下的資料夾 id，例如 `15kYNAy8PwyNyIubTE-dhtPXJlg9o3Z-A`。
4. 按「Add variable」。

### 3. 允許自動開 Pull Request

1. 左側「Actions」→「General」。
2. 拉到最下面「Workflow permissions」。
3. 勾選「**Allow GitHub Actions to create and approve pull requests**」。
4. 按「Save」。

沒勾這個的話，同步會成功但開 Pull Request 那一步會失敗。

## 六、手動跑一次、看結果

1. 專案頁上方「Actions」分頁。
2. 左側點「同步雲端硬碟圖片」。
3. 右邊「Run workflow」→ 分支保持 `main` →「Run workflow」。
4. 幾秒後清單出現一筆執行紀錄，點進去可以看每個步驟。
   - 綠色勾勾：成功。
   - 紅色叉叉：失敗，點進「同步圖片」步驟看訊息（常見原因見下方「常見問題」）。
5. 「同步圖片」步驟的訊息會列出新增、更新、刪除了哪些圖片，以及被略過的檔案（「警告：…」開頭）。
6. 如果有變更，「Pull requests」分頁會出現一個「同步雲端硬碟圖片」的 Pull Request，說明欄有新增／更新／刪除的數量與清單。
7. 在 Pull Request 的「Files changed」分頁可以直接預覽圖片。確認沒問題 →「Merge pull request」→「Confirm merge」。

沒有任何變更時不會開 Pull Request，這是正常的。

之後每天台灣時間凌晨 3 點左右會自動跑一次。上一個 Pull Request 還沒合併時，新的同步會更新同一個 Pull Request，不會一直開新的。

### 合併後網站多久更新？

合併後 GitHub Pages 會自動重新發布，通常 1～5 分鐘。可以在「Actions」分頁看到一個「pages build and deployment」的執行紀錄，變成綠色勾勾就好了。瀏覽器可能有快取，看不到新圖時按 `Ctrl`＋`F5`（Mac 是 `Cmd`＋`Shift`＋`R`）重新整理。

## 七、試算表發布到網路（網站文字資料）

網站的文字資料（成員介紹、相簿說明等）來自「第一交響樂團｜網站資料（網站用）」試算表。要讓網站讀得到，每個分頁要各自發布成 CSV：

1. 打開試算表 → 上方選單「檔案」→「共用」→「發布到網路」。
2. 「連結」分頁裡，第一個下拉選單選要發布的**分頁**（例如 `members`），第二個選「**逗號分隔值 (.csv)**」。
3. 按「發布」→ 確認，複製出現的網址（會像 `https://docs.google.com/spreadsheets/d/e/…/pub?gid=0&single=true&output=csv`）。
4. 每個分頁重複一次，記下「分頁名稱 → 網址」。
5. 打開 GitHub 專案裡的 `assets/js/config.js`，把對應的表改成：

   ```js
   members: { source: 'csv', url: '貼上剛剛複製的 CSV 網址' },
   ```

   其他分頁照同樣方式改。檔案裡有哪些表、怎麼填，以 `config.js` 裡的說明為準。
6. 存檔、提交到 `main`。

> 發布到網路的內容任何人都看得到，只放可以公開的資訊（遊戲暱稱、說明文字），不要放真實姓名或聯絡方式。試算表改內容後，網站通常 5 分鐘內會讀到新內容，不需要重新發布。

## 八、管理員日常流程

### 新增相簿照片

1. 到「投稿區」看成員丟的照片，挑出要放上網站的。
2. 複製或移動到「管理員專用 / 網站相簿 / <分類>」底下的相簿資料夾。
   - 分類固定 6 個：團體合照、副本、節日活動、演奏、日常、紀念日。不要新增其他分類資料夾（會被略過）。
   - 一本相簿＝一個資料夾，名稱寫「`年-月 標題`」，例如 `2010-08 夏日合奏`（年 4 碼、月 2 碼，中間空一格）。
   - 照片檔名隨意，相簿內依檔名排序。想控制順序可以取 `01.jpg`、`02.jpg`…
3. 到試算表「相簿」分頁補一列：`album` 欄填相簿資料夾名稱（要一字不差），再填說明等欄位。
4. 等隔天自動同步，或到 Actions 手動執行。
5. 檢查 Pull Request，合併。

### 成員頭像與造型

- 放在「成員 / m01-暱稱」資料夾，資料夾名稱開頭的 `m01` 要和網站的成員編號一樣；後面的暱稱可以隨時改。
- 頭像檔名 `頭像.jpg`（png、webp 也可以），會自動縮成 400×400 以內。
- 造型檔名 `造型-1.jpg`、`造型-2.png`…，會自動縮到高度 900 以內。
- 同一個資料夾裡不要同時放 `頭像.jpg` 和 `頭像.png`，只會用其中一張。

### 橫幅與故事配圖

- 「橫幅與故事配圖」資料夾裡放 `橫幅.*` 和 `故事配圖.*`。要換圖就直接覆蓋或換一張同名的。

### 刪除或替換

- 雲端硬碟刪掉照片，下次同步網站上的那張也會刪除。
- 換掉同名檔案（例如新的 `頭像.png`），下次同步會更新。
- 照片移到別本相簿：照片會跟著換相簿，不用另外處理。

## 常見問題

| 狀況 | 原因與處理 |
|---|---|
| 「缺少環境變數 GDRIVE_SA_KEY」 | 第五步的 Secret 沒建，或名稱拼錯。 |
| 「GDRIVE_SA_KEY 不是有效的 JSON」 | 貼金鑰時少貼了開頭或結尾，重新貼整個檔案內容。 |
| 「缺少資料夾 id」 | 第五步的 Variable 沒建，或建到 Secrets 去了（要在 Variables 分頁）。 |
| `File not found` 或 `404` | 資料夾沒分享給 service account（第四步），或資料夾 id 填錯。 |
| `Drive API has not been used` | 第二步沒有啟用 Google Drive API，或啟用在別的專案。 |
| 同步成功但沒有 Pull Request | 沒有任何變更；或第五步第 3 點沒勾，此時「開或更新 Pull Request」步驟會是紅色。 |
| 某張照片沒出現 | 看執行紀錄或 Pull Request 說明裡的「警告」，常見是資料夾名稱格式不對、檔名不對、或檔案格式不支援（支援 jpg、png、webp、gif、bmp、tif；iPhone 的 HEIC 請先轉成 jpg）。 |

## 給維護程式的人

- 程式：`tools/sync_drive_images.py`；套件：`tools/requirements.txt`；排程：`.github/workflows/sync-images.yml`。
- 本機測試（不連 Google）：準備一個相同結構的資料夾，執行

  ```bash
  pip install Pillow
  python3 tools/sync_drive_images.py --local <資料夾> --repo <輸出用的暫存資料夾>
  ```

  不加 `--repo` 會直接寫進專案（會蓋掉現有的圖片與 `data/gallery.json`），測試完記得還原，不要 commit 測試產物。
- 規格與路徑表見 `docs/spec.md` 第八節。
