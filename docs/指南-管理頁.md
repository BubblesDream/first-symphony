# 管理頁安裝與使用指南

管理頁是一個**只有你自己能開**的網頁，用來一筆一筆補成員、歷史、會長與相簿，不用再直接改試算表與雲端資料夾。它是 Google Apps Script 網頁應用程式，綁在「網站用」試算表上，不需要另外架伺服器，也**不是網站的一部分**（程式在 `tools/admin/`，不會部署到 GitHub Pages）。

圖片仍由原本的 GitHub Action 同步到網站（見 `docs/指南-圖片同步設定.md`）。管理頁只負責把檔案放進正確的雲端資料夾、取正確的檔名。

> 這份程式**還沒有實機測試**（開發環境無法執行 Apps Script）。第一次使用請先拿一筆不重要的資料試試看，確認沒問題再大量使用。刪除動作都是「移到雲端硬碟垃圾桶」，不會永久刪除。

---

## 一、安裝

### 1. 打開 Apps Script

1. 開啟「第一交響樂團｜網站資料（網站用）」試算表。
2. 上方選單「擴充功能」→「Apps Script」，會開一個新分頁。

### 2. 顯示 appsscript.json

1. 左邊齒輪「專案設定」。
2. 勾選「在編輯器中顯示『appsscript.json』資訊清單檔案」。
3. 回到左邊「編輯器」（`< >` 圖示），會看到 `appsscript.json`。

### 3. 貼上程式（共 6 個檔案）

專案裡原本有一個 `Code.gs`。對照 GitHub 專案 `tools/admin/` 資料夾，逐一處理（左邊檔案清單旁的「＋」可新增檔案；`.gs` 選「指令碼」，`.html` 選「HTML」；新增時**不用打副檔名**）：

| 檔名（在 Apps Script 裡） | 類型 | 來源 |
|---|---|---|
| `Code` | 指令碼 | `tools/admin/Code.gs`（貼進原有的 Code.gs，整個覆蓋） |
| `Logic` | 指令碼 | `tools/admin/Logic.gs` |
| `Index` | HTML | `tools/admin/Index.html` |
| `Style` | HTML | `tools/admin/Style.html` |
| `Script` | HTML | `tools/admin/Script.html` |
| `appsscript.json` | 資訊清單 | `tools/admin/appsscript.json`（整個覆蓋） |

每個檔案：打開 GitHub 上的原始檔 → 全選複製 → 貼到對應檔案、全選覆蓋 → `Ctrl+S` 儲存。

> 檔名大小寫要完全一樣（`Index`、`Style`、`Script`），程式是用這些名字互相引用的。

### 4. 確認資料夾設定

打開 `Code` 檔案最上方，有三個常數：

```js
var SPREADSHEET_ID = '…';        // 「網站用」試算表 id（備用）
var ADMIN_ROOT_FOLDER_ID = '…';  // 管理員專用資料夾
var INBOX_ROOT_FOLDER_ID = '…';  // 投稿區相簿資料夾
```

資料夾 id 是網址 `https://drive.google.com/drive/folders/` 後面那一串。**搬家、換資料夾時只要改這裡**，改完重新部署（見第三節）。

管理員專用資料夾底下需要有：`成員/`、`網站相簿/`、`橫幅與故事配圖/`（`歷史配圖/` 不存在會自動建立）。

### 5. 部署為網頁應用程式

1. 右上角「部署」→「新增部署作業」。
2. 左邊齒輪「選取類型」→「網頁應用程式」。
3. 說明隨意填（例如「管理頁」）。
4. **執行身分：我**。
5. **誰可以存取：只有我自己**。
6. 按「部署」。

### 6. 授權

第一次部署會要求授權，Google 會顯示「**Google 尚未驗證這個應用程式**」的警告。這是正常的（這個程式是你自己寫在自己的試算表裡，沒有送 Google 審核）：

1. 選你的 Google 帳號。
2. 在警告畫面按左下角「**進階**」。
3. 再按「**前往『（專案名稱）』（不安全）**」。
4. 檢查權限（讀寫試算表、雲端硬碟），按「**允許**」。

完成後會出現網頁應用程式網址（`https://script.google.com/macros/s/…/exec`）。**複製它並加入瀏覽器書籤。** 忘了網址時，回到試算表選單「網站管理」→「開啟管理頁」就會顯示。

> 第一次重新整理試算表後，上方會多出「網站管理」選單（需要等幾秒）。

## 二、日常使用流程

建議順序：**先轉換 → 成員一個一個補 → 歷史 → 會長 → 相簿**。

### 先做兩個一次性轉換

試算表選單「網站管理」：

1. **轉換：歷任會長改用 period**：把 `term_start`、`term_end` 合併成 `period`，加上 `sort_order`。（例：`2005`＋空白 → `2005～`）
2. **轉換：相簿改成一本相簿一列**：把「相簿」分頁改成新欄位。若有舊資料，會先複製一份備份分頁。

兩個都可以重複執行，已經轉換過會告訴你「不需要再轉換」。第一次執行選單會要求授權，照第一節第 6 步按「進階 → 前往」。

### 成員

- 左邊清單顯示每位成員的完成度：頭像、自我介紹、造型幾張；勾「只看缺資料的」可以只看還沒補完的。
- 右邊填表後按「儲存」，再按「下一位 →」。
- 頭像／造型：按「上傳」選圖片（jpg、png、webp、gif，每張 20MB 以內）。會存成 `成員/mXX-暱稱/頭像.副檔名`、`造型-n.副檔名`，換頭像時舊的移到垃圾桶。
- 「新增成員」會自動給下一個 id（m27…）並建立資料夾。改暱稱時，資料夾名稱 `-` 後面一併更新，id 不動。

### 歷史

- 日期可以寫模糊：`2008`、`2008-09`、`2008 左右`、`約 2008`。
- 內容一兩句即可（選填），也可以放影片網址、配圖。配圖要先儲存這一筆，再回來上傳。

### 歷任會長

- 暱稱可從成員下拉選，或自己輸入；任期 `period` 自由填寫。
- 清單旁 ↑↓ 可調整順序（越早越上面）。

### 相簿

1. 「從投稿區挑照片」：點資料夾一層層進去，縮圖一頁 30 張，按「載入下一頁」看更多。勾選照片 → 選分類 → 選現有相簿或新建（輸入 `YYYY-MM` 與標題）→「加入網站相簿」。照片是**複製**，投稿區原檔不會動。已經在網站相簿的照片會標「已在網站相簿」。
2. 「管理網站相簿」：編輯相簿標題、說明、遊戲、精選；可展開照片並移除（移到垃圾桶）。

### 公會設定

逐列編輯 key／value，每列各自按「儲存此列」。橫幅與故事配圖在這一頁上傳，舊檔會移到垃圾桶。

### 儲存之後多久上線

- 文字：約 5 分鐘內反映到網站（試算表發布到網路的更新時間）。
- 圖片：下一次同步（每天凌晨 3 點，或到 GitHub 的 Actions 手動執行）會開 Pull Request，合併後上線。

## 三、程式更新時重新部署

以後專案裡的 `tools/admin/` 有更新時：

1. 照第一節第 3 步，把有變動的檔案重新貼進 Apps Script，儲存。
2. 右上角「部署」→「管理部署作業」。
3. 點目前那個部署旁的鉛筆（編輯）。
4. 「版本」選「**新版本**」→「部署」。

網址**不會改變**，書籤照用。（不要選「新增部署作業」，那會產生另一個新網址。）

## 四、遇到問題

| 狀況 | 怎麼辦 |
|---|---|
| 說「找不到試算表分頁」 | 分頁名稱要是：成員、造型、相簿、歷史、歷任會長、公會設定 |
| 說「第 1 列缺少欄位」 | 歷任會長／相簿請先做轉換；其他分頁對照 `docs/spec.md` 第五節補上欄位 |
| 縮圖顯示「無縮圖」 | Google 還沒產生縮圖，或檔案格式不支援；不影響上傳與同步 |
| 開啟網址顯示沒有權限 | 要用部署時的同一個 Google 帳號登入 |
| 修改程式後畫面沒變 | 要重新部署新版本（第三節） |

## 五、安全提醒

- 部署時務必選「只有我自己」；管理頁能讀寫整個管理員資料夾。
- 程式不會把任何檔案改成公開分享。縮圖是由後端轉成圖片資料傳回畫面。
- 程式只會動管理員專用資料夾；投稿區只讀取、複製，不修改。
