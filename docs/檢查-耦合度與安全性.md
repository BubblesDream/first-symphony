### 1-3 【中】城堡程式在「載入模組時」就需要全域 `Phaser`，導致備援訊息與公會歌一起失效

- 位置：`assets/js/castle/RoomScene.js:15`（`export class RoomScene extends Phaser.Scene`）、`assets/js/pages/hall.js:3-4`（靜態 `import`）、`assets/js/pages/hall.js:24-27`（`if (!window.Phaser)` 的檢查）、`assets/js/pages/hall.js:9-10`（公會歌）。
- 現象：`hall.js` 用靜態 `import` 引入 `castle/main.js` → `RoomScene.js`。`RoomScene.js` 一被載入就要讀 `Phaser.Scene`。如果 `phaser.min.js` 沒載到（404、被瀏覽器外掛擋、網路斷），整個模組在執行前就丟出 `ReferenceError: Phaser is not defined`，`hall.js` 一行都不會跑。（已用 Node 實測：載入 `RoomScene.js` 直接失敗。）
- 後果：
  - 畫面永遠停在「城堡載入中…」，`hall.js:24` 寫好的「遊戲程式載入失敗，請重新整理」不會出現。
  - `hall.js:8` 註解說「遊戲載入失敗也能聽歌」，實際上公會歌按鈕也不會出現，和交接文件的設計相反。
  - 頁首、頁尾（`initLayout()`）也不會畫出來。
- 建議（小改，值得現在改）：`pages/hall.js` 保留靜態 import `layout.js`、`data.js`、`castle/music.js`，把城堡改成確認有 Phaser 之後才動態載入：
  ```js
  if (!window.Phaser) { fail('遊戲程式載入失敗…'); return; }
  const { startCastle } = await import('../castle/main.js');
  ```
  這樣「遊戲壞掉」和「網頁其他部分」就真的分開了。

## 二、安全性

### 2-0 已確認沒問題的地方（好消息）

- **XSS**：在 `assets/js/`、所有 `*.html`、`tools/admin/` 搜尋 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`、`eval(`、`new Function`、`setAttribute('on…')`：**全部沒有**（只出現在「不用 innerHTML」的註解裡）。外部資料都用 `textContent`／`createElement`（`render.js` 的 `el()`、`dialog.js`、`music.js`、管理頁 `Script.html:13-23`）。城堡畫布上的暱稱與泡泡用 Phaser 文字物件，不經過 HTML。
- **連結**：`href` 只用固定頁名、`encodeURIComponent(id)`（`members.js:15`、`home.js:114`、`story.js:86`）或 `youTubeWatch(id)`；`target="_blank"` 兩處（`ui.js:146-152`、`story.js:32-35`）都有 `rel="noopener noreferrer"`。
- **`validate.js`**：實測擋下 `javascript:`（含大小寫混用）、`data:`、`//evil.com`、`/assets/…`、`assets/../`、`assets/%2e%2e/`、含空白或控制字元的網址；YouTube 只接受固定網域，ID 嚴格 11 碼，嵌入網址由程式重新組合。
- **URL 參數**：`?id=` 只拿來比對，不放進畫面或網址；`?seed=`、`?npcs=` 只接受純數字（`pages/hall.js:48`）；`?npcs=999999` 會被房間總容量（57）與成員人數（26）限制住，不會卡；`?debug=1` 只是把遊戲狀態放到 `window.__castle`，沒有秘密資料。`?moon=`、`?room=`、`?meet=` 在主目錄**還不存在**（只在 `docs/構想-訪客與成員想要的功能.md:79` 的構想裡）。
- **localStorage／sessionStorage／shareImage**：主目錄沒有使用。城堡圖片都是同網域，畫布不會被跨來源圖片污染。

### 2-1 【中】GitHub Action 的第三方程式沒有固定版本，而且有寫入權限的 token 會留在環境裡

- 位置：`.github/workflows/sync-images.yml:11-13`（整個 workflow 都是 `contents: write`、`pull-requests: write`）、`:25`（`actions/checkout@v4`）、`:28`（`actions/setup-python@v5`）、`:45`（`peter-evans/create-pull-request@v7`）、`:35`（`pip install`）；`tools/requirements.txt`（`Pillow>=10.0` 沒有上限，其他是範圍）。
- 現象：
  - Action 用「標籤」（`@v4`）而不是固定的 commit SHA。標籤可以被作者（或盜用作者帳號的人）改指到別的程式碼。
  - Python 套件每次安裝最新版。
  - `actions/checkout` 預設會把有寫入權限的 `GITHUB_TOKEN` 存進 `.git/config`，之後的 `pip install` 與 Python 程式都讀得到。
- 可能後果（具體情境）：某天 Pillow 的某個相依套件或某個 action 被植入惡意程式 → 在每天凌晨的同步中執行 → 用 token 直接推一個改過的 `assets/js/data.js` 到 `main`（如果 `main` 沒有分支保護）→ 所有訪客載入惡意 JS。機率不高，但後果是整個網站被改。
- 建議：
  1. 三個 action 改成固定 SHA，例如 `actions/checkout@<40 碼 SHA> # v4.x.x`。
  2. `requirements.txt` 固定確切版本（`Pillow==11.x.x`），想更新時再手動改。
  3. `main` 開分支保護（要求 PR、禁止直接推送）——這是最便宜、效果最大的一步。
  4. 進一步：拆成兩個 job，轉檔 job 只給 `contents: read`，把產出的檔案當 artifact 傳給開 PR 的 job 再給寫入權限（見「待確認」第 4 點）。

### 2-2 【中】所有頁面都沒有 Content-Security-Policy

- 位置：`index.html`、`members.html`、`member.html`、`story.html`、`videos.html`、`gallery.html`、`hall.html:3-19`、`404.html` 的 `<head>` 都沒有 `<meta http-equiv="Content-Security-Policy">`。
- 現象：目前程式沒有 XSS 洞，但 CSP 是「萬一以後有人不小心寫了 innerHTML」或「第三方檔案被換掉」時的第二道防線。
- 可能後果：未來若出現一個注入點，瀏覽器不會阻擋外部腳本執行或把資料送到其他網站。
- 建議（要實際測過再上線）：GitHub Pages 只能用 meta。起點可以是：
  ```
  default-src 'self';
  script-src 'self';
  style-src 'self' https://fonts.googleapis.com;
  font-src https://fonts.gstatic.com;
  img-src 'self' https: data: blob:;
  media-src 'self';
  frame-src https://www.youtube-nocookie.com;
  connect-src 'self' https://docs.google.com https://*.googleusercontent.com;
  object-src 'none'; base-uri 'self'; form-action 'none'
  ```
  注意：`404.html:8-39` 有一段內嵌 `<script>`，要改成外部檔或加 `'sha256-…'`；`base-uri 'self'` 和 404 頁用程式設定 `<base>` 的做法要一起測；Phaser 內建貼圖會用 `data:`／`blob:`；試算表 CSV 啟用後 `connect-src` 要涵蓋實際轉址的網域。meta CSP 不支援 `frame-ancestors`。

### 2-3 【低】資料表的值可以「撞到」JavaScript 物件內建屬性
